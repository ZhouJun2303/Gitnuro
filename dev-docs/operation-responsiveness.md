## 1. 目标和执行模型

界面立即响应，耗时工作在后台执行；预期结果带等待标记，真实成功、当前分支、提交 ID 和冲突结果由后台确认。目标同时包括减少实际工作量和缩短用户等待下一次交互的时间。

操作刚入队时，Git 可能尚未执行。此时立即读取仓库状态可能得到旧结果，产生回跳并增加扫描。入队阶段先更新任务状态或预期显示，执行后再读取真实状态。

界面状态由两部分组成：后台已确认的真实快照，以及尚未完成操作的预期显示。后台结果返回后更新真实快照，再根据剩余任务重新计算显示；失败或部分成功也按实际状态对账。

任务按以下方式调度：

- 写操作按仓库保序；不同仓库可以并行，附加工作树共享的引用和配置也要协调。
- 读取按需求调度。稳定提交对象可并发读取；工作区和索引读取需要与写入状态、数据版本对齐。
- 滚动、选择、输入、布局等本地交互即时处理，忙碌状态按任务及其影响范围管理。
- 当前可见内容优先，后台预取限量、低优先；旧预览和过期搜索及时淘汰。
- 操作完成、状态核验、辅助内容加载分别结束；下一次操作只等待它真正依赖的结果。
- 任务依赖明确。例如“暂存 → 提交 → 推送”必须按实际成功结果推进；失败或冲突会暂停相关后续写操作。

后端任务登记和写入通道以 common Git directory 为键，附加工作树共享顺序；桌面窗口通过事件共享状态，试验台通过轮询读取同一登记表。前端固定任务输入、建立依赖并展示预期结果，状态核验与历史、差异等辅助读取独立结束。账户、AI、字体、更新及外部工具为独立服务任务，不占用仓库写入队列。

## 3. 所有操作共用的后台机制

| 机制 | 应有行为 |
| --- | --- |
| 写操作调度 | 按仓库保序；附加工作树共享的引用和配置也要协调 |
| 读取调度 | 提交对象等稳定数据可并发读取；工作区读取需要版本校验 |
| 优先级 | 用户当前需要的任务优先，空闲预取低优先；保留写操作依赖顺序 |
| 文件监听 | 合并事件，记录受影响路径；监听建立后补一次状态对账 |
| 刷新范围 | 工作区、索引、引用、历史、贮藏、配置分别决定是否刷新 |
| 连续操作 | 合并重复读取和后续校验；写操作按其语义保留顺序 |
| 缓存 | 历史内容按提交 ID、路径及参数复用；工作区内容随版本失效 |
| 大列表和差异 | 虚拟滚动、分页、分帧计算，可见内容优先 |
| 忙碌状态 | 按任务及受影响内容管理，浏览、滚动、输入保持可用 |
| 失败和部分成功 | 读取实际结果，再结合剩余待执行任务重新计算界面 |
| 冲突 | 暂停依赖冲突结果的后续写操作，继续允许浏览和解决冲突 |
| 多窗口 | 共享仓库任务状态和版本，避免重复执行或相互覆盖 |
| 计时 | 分开记录排队、Git 执行、核验、界面更新及重新可操作的时间 |

## 4. 实施边界

### 4.1 任务目标和数据版本

- 入队时固定用户选中的仓库、文件、分支、远程、选项和说明；执行时检查前置状态及任务依赖。
- 逐行、逐块操作绑定当时显示的内容和补丁版本，执行前校验；排队后仅凭行号或差异块序号不足以定位修改。
- 贮藏绑定提交 ID，避免其他操作改变 `stash@{n}` 序号后恢复错误条目。
- 提交结束时只处理本次任务拥有的草稿，保留用户后来输入的新内容。AI 结果同样校验输入版本和编辑状态。
- 缓存和异步结果关联仓库、内容版本及读取参数；旧结果和旧错误都不能覆盖新仓库、新选择或新状态。
- 待执行任务的预期显示不作为实际提交、推送或本地修改保护的依据。

### 4.2 写入、恢复和取消

- 保留现有 Git 参数、hooks、过滤器、行尾和本地修改保护语义；具体约定见[开发文档](development.md)。
- 自动贮藏的保存、主操作和恢复属于同一任务的依赖阶段，恢复结果参与任务最终状态。
- 批量任务可能部分成功。根据实际 Git、索引和文件结果对账，再应用剩余任务的预期显示。
- 取消待执行任务需要检查后续依赖；取消运行中任务需要结束实际进程，并核验可能已发生的修改。
- 取消和进度控制需要独立响应，不能排在被取消任务之后等待；实际恢复、中止等仓库写入仍与其他写入协调。
- 用户前台任务优先影响尚未开始的调度；运行中任务按其可取消能力处理，保留已有执行结果。

### 4.3 刷新和预取

- 按实际影响分别失效工作区、索引、引用、历史、贮藏及配置；保留未变化的数据对象和界面位置。
- 连续操作合并重复读取和后续整仓校验；仍保留外部 Git、编辑器和文件系统变化的监听与对账。
- 列表和索引更新核验完成后，下一次写操作只等待自身依赖的状态；差异预览、历史绘制和统计独立加载。
- 预取限于可复用的读取，设置数量、并发及缓存上限；需要显式发起的写入和服务请求仍由用户操作触发。
- 按需读取及后台执行也需要控制主线程开销，包括排序、树构建、提交图、高亮、图片计算和整表比较。

### 4.4 共用入口

1. [任务入口](../src/lib/tasks.ts)和[后端登记表](../src-tauri/src/tasks.rs)：固定任务身份、输入、依赖和取消状态；倒序或交错交付也按依赖排序，失败、冲突和取消阻断后续依赖，解决冲突与恢复操作可以继续。
2. [读取调度](../src/lib/read-scheduler.ts)：合并同参数读取，用户当前读取优先；同时最多 4 项，其中可变状态读取最多 2 项，预取最多 1 项。稳定对象缓存最多 100 项、24 MiB，单项超过 12 MiB 不缓存；可变内容在写入开始和结束时失效。
3. [刷新分类](../src/lib/operation-policy.ts)和[后端操作分类](../crates/git/src/ops.rs)：穷举操作的影响范围，元数据操作省去工作区扫描。监听事件合并路径；元数据变化和事件溢出回退完整对账。
4. [任务面板](../src/lib/shell/TaskQueue.svelte)：展示活动任务和最近 15 项结果，虚拟滚动，区分排队、运行、核验、取消中、冲突和失败。自动贮藏保存、获取、整合和恢复阶段复用流程事件。登记表保留有界历史，同时保护仍被活动任务引用的依赖结果。

验收分别观察点击反馈、真实 Git 完成、列表核验、下一次操作可执行和辅助内容加载时间，并核对失败、冲突、连续操作、外部修改及多窗口下的最终状态。性能数据和回归结果记录到[项目性能优化计划](performance-plan.md)。

## 5. 九类操作的代码覆盖

| 清单 | 实现与核验路径 |
| --- | --- |
| 2.1 文件和暂存区 | 整文件操作通过 `staging.ts` 叠加预期列表；块和行操作固定仓库、文件、侧别、参数与差异指纹，过期内容拒写；删除、丢弃、恢复及忽略规则使用路径等待状态。粘贴补丁先打开表单并解析文件清单，应用后按实际状态对账。 |
| 2.2 提交和整合 | 提交固定说明、选项和分支；只清理仍属于该任务的草稿。提交和推送同时入队，推送依赖真实提交结果，辅助历史不阻塞推送。整合、历史改写、重置和二分走同一写入通道，冲突以真实流程为准。 |
| 2.3 引用和远程 | `projectRefs` 单独投影新分支、标签、远程和更名，等待标记不改变真实引用或当前分支。确认回调固定目标仓库和参数；隐式当前分支的推送、拉取在执行前检查分支。只有引用标签变化时更新装饰，不重读已存在的历史。 |
| 2.4 贮藏和冲突 | 贮藏固定完整提交 ID，补丁为可复用读取。自动贮藏保存、主操作与恢复属于同一任务，恢复结果决定最终状态；手工冲突编辑保存前校验版本。解决、继续、跳过及中止不依赖失败任务的成功结果。 |
| 2.5 仓库扩展 | 克隆、初始化按目标目录排队，不要求已经打开仓库；工作树、子模块、LFS 和 Git Flow 统一登记任务并按实际影响刷新。创建中的工作树和子模块先展示条目及等待标记，下载与整合进度分别更新。 |
| 2.6 读取浏览 | 仓库视图缓存有界，读取绑定仓库、打开代次和选择参数；旧结果与旧错误均丢弃。提交历史、文件历史、搜索和 Reflog 分页追加。Blame 正文先到，可见归属按 200 行读取，正文预览最多 2 MB / 50,000 行。目录扫描持有后端游标，每页最多遍历 128 项、约 20ms 或返回 16 个仓库，最多发现 300 个仓库；游标最多 16 个、闲置 5 分钟过期。图片和大差异复用已有 worker、限量预览、虚拟化和可见区高亮。 |
| 2.7 界面和设置 | 本地交互与仓库任务解耦。设置保存延迟 80ms 合并，写入按设置通道串行化，以修改前基线逐字段和记录 ID 合并，保留其他窗口及等待期间的编辑。导入配置同样三方合并；窗口位置继续合并保存。 |
| 2.8 账户和 AI | 账户发现、测试与登录为独立服务任务，返回值按字段和 ID 合并；取消登录、设备轮询及编辑代次淘汰旧结果。通知先移除，失败只恢复该项。AI 提交说明与审查校验原始暂存版本或提交范围及当前编辑上下文；连接和模型结果校验 URL 与密钥，失败保留已有列表。 |
| 2.9 工具和维护 | 外部工具、历史副本、输出、字体和更新显示独立任务，保留各自的下载、启动及错误反馈；关闭更新或重新检查后，旧检查的结果和错误均丢弃。本地剪贴板和选择器继续即时调用。取消控制独立于写队列，未交付请求记录取消标记，运行中请求结束真实进程树，核验后结束；后续命令检查取消标记，保留已完成的写入和恢复结果。 |

任务输入及版本、投影与真实快照、读取调度和设置合并分别由 `operation-scheduler`、`responsiveness`、`tasks::tests`、`settings_merge::tests` 覆盖；真实界面回归与验证结果维护在[性能记录](performance-plan.md)。后端排队、执行、核验计时和前端关联请求的 backend / refresh / wait / total 计时分别保留，不把列表即时变化等同于实际 Git 完成。
