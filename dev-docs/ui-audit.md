### 测量口径

- 在本机 Windows 的 Playwright Chromium、Vite 开发服务与 Rust 试验台后端上使用一个 worker 顺序运行。`readyMs` 是导航至场景就绪的时间，包含模块加载和仓库初始化读取；截图时间单独计入 `loadMs`，不当作弹窗打开时间。
- 主线程长任务由 Long Tasks API 记录，采集到截图检查结束；`maxTaskMs` 为单个最长任务。表中 0 仅表示没有观察到 50ms 以上任务。每条后台命令另记录请求起点和响应结束耗时，不能将并发命令耗时相加当作页面等待。
- 每个主题/场景保存一份最终通过样本，复验覆盖同名样本；下列中位数/p95 是不同场景之间的分布，不是单个场景重复采样的统计。开发服务的缓存与加载成本会影响就绪时间。
- 压力用例通过只读响应桩提供 4,000 条提交/分支；批量选择用例处理 20,000 个路径，Git 写入使用桩，测量的是前端函数。前后对照使用相同正常账户服务；早期受限账户产生的权限错误样本不参与性能结论。这些数据不能代表安装包、真实 Git 写操作或网络的整体提速比例。
- 原始 JSON、截图、首轮超时记录保存在忽略目录 `.lab/ui-audit/2026-11-17-before/` 和 `.lab/ui-audit/2026-11-17-after/`。运行入口和记录字段见 [开发文档](development.md#测试)。
